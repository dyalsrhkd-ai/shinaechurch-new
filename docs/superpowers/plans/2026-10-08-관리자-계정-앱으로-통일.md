# 관리자 계정 앱으로 통일 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** 앱에서 「승인된 관리자」인 계정으로 홈페이지 관리자에 로그인하고, 앱관리 칸은 다시 로그인하지 않게 한다. 지금 홈페이지 계정은 비상용으로 남긴다.

**Architecture:** Worker 에 서버끼리만 쓰는 `POST /admin-login`(공유 키 헤더) → 운영 `auth.php` 가 비상용 계정 확인에 실패하면 Worker 에 묻고, 통과하면 `admin_users` 그림자 줄(uid = 앱 uid, login_id = `app-<uid>`)로 세션을 연다. 응답의 `appSession` 을 다리 스크립트가 받아 앱관리 칸이 틀 안 앱에 `postMessage` 로 넘긴다.

**Tech Stack:** Cloudflare Worker(node:test), PHP 5.5(카페24, `??`·타입힌트·random_bytes 금지), 다리 스크립트(plain JS), React 앱 관리 모드.

## Global Constraints
- 기준은 앱 계정. 홈페이지에 들어가는 건 `members.role = 'admin'` 이고 `status = 'approved'` 인 계정만(부관리자 staff 는 못 들어감).
- 비상용(비밀번호 있는 `admin_users`) 계정이 **먼저** 확인된다 — 앱 서버가 멈춰도 들어갈 길.
- Worker 공유 키 `ADMIN_LOGIN_KEY`: Worker secret + 운영 `api/_app_login_key.php`(FTP 로만, 깃·대화에 값 남기지 않음).
- 실패 문구는 하나(「아이디 또는 비밀번호가 맞지 않습니다」) — 관리자 여부를 흘리지 않는다. 앱 서버 무응답만 따로 안내.
- 운영 PHP 는 받아서 필요한 곳만 고치고 백업 후 올린다. 홈페이지 저장소의 남의 미커밋 변경은 커밋하지 않는다.

### Task 1: Worker `POST /admin-login`
**Files:** Create `shinae-community/media-worker/src/admin-login.js`, `shinae-community/tests/admin-login-worker.test.js`; Modify `media-worker/src/index.js`(출처 검사 **앞**에 경로 연결)

- [ ] 실패 시험: 키 없음/틀림 403, 관리자 승인 200 + `{ uid, name, access_token, refresh_token }`, 교인·부관리자·대기·정지 401, 틀린 비밀번호 401, 빈도 초과 429, Supabase 무응답 502. 아이디(`login_email_for`)·휴대폰(`p<번호>@members.shinae.invalid`)·`admin` 별칭 모두.
- [ ] 구현: 키 비교(상수 시간) → `consume_signup_limit`(`admin-login:<identity>` 10회) → 이메일 결정(앱 `loginEmail` 과 같은 규칙, 아이디는 `login_email_for`) → `/auth/v1/token?grant_type=password` → `/rest/v1/members?id=eq.<uid>&select=name,role,status`(service key) → 관리자·승인일 때만 토큰.
- [ ] `npm test` 통과 → Worker 배포(`cd media-worker; npx wrangler deploy`), `npx wrangler secret put ADMIN_LOGIN_KEY`(표준입력) → 커밋.

### Task 2: 운영 PHP — 비상용 먼저, 아니면 앱 관리자
**Files:** Create `shinaechurch-new/public/api/_app_admin_service.php`, `tests/php/app_admin_service_test.php`; Modify `public/api/_auth_service.php`(세션 여는 부분을 `auth_open_session()` 으로 분리), `public/api/auth.php`(login 실패 시 앱 경로), 운영 전용 `api/_app_login_key.php`(깃 제외)

- [ ] `_app_admin_service.php`: `app_admin_check($identity, $password)` — curl POST Worker `/admin-login`(8초, 헤더 `X-Admin-Login-Key`), 결과 `array('ok'=>true,'uid','name','session'=>array(access,refresh))` / `array('ok'=>false,'kind'=>'denied'|'unavailable')`. `app_admin_shadow($repository, $uid, $name)` — `login_id = 'app-'.$uid` 줄을 찾아 쓰거나(이름 갱신) 만든다(uid = 앱 uid, 비밀번호는 쓸 수 없는 무작위 해시, must_change_password 0). 지워진 줄이면 아이디 비우고 새로.
- [ ] `auth.php` login: 기존 `auth_login` 실패 → 아이디 모양이 앱 규칙(`/\A[A-Za-z0-9][A-Za-z0-9._@+()\- ]{2,99}\z/`)이면 `app_admin_check` → 통과면 그림자 줄 + `auth_open_session` + 응답에 `appSession`. 무응답이면 503 「앱 서버에 연결하지 못했습니다 — 비상용 계정으로 들어가세요」.
- [ ] PHP 5.5 문법만(배열 `array()`, `??` 없음, 타입힌트 없음). 로컬에 PHP 가 없어 시험 파일은 남기되 실행은 운영 확인으로 대신.
- [ ] 운영 반영: 운영 `auth.php`·`_auth_service.php` 가 로컬과 같은지 대조 → 백업 → 올림 → 받아 대조 → 비상용 계정 로그인 확인(요셉님).

**Files:** Modify `shinae-community/src/embed.js`·`src/App.jsx`·`src/live-store.js`·`src/demo-store.js`, `shinaechurch-new/public/app-install-links.js`·`public/app-admin-panel.js`, `scripts/app-admin-browser.mjs`

- [ ] 앱(관리 모드): 시작하면 부모에 `{type:'shinae-embed-ready'}` 를 보내고, 부모가 홈페이지 주소(`http(s)://(www.)shinaechurch.co.kr`, 시험용 localhost/127.0.0.1)일 때만 `{type:'shinae-embed-session', access_token, refresh_token}` 을 받아 `store.adoptSession()`(live: `client.auth.setSession`, demo: 관리자 데모로 입장) — 이미 로그인돼 있으면 무시.
