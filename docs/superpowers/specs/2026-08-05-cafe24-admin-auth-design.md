# 카페24 관리자 인증·계정 관리 설계

## 목표

Firebase Auth와 관리자 세션용 Firestore 의존성을 제거하고, 교회 명의의 카페24 계정 안에서 관리자 로그인과 계정 관리를 운영한다. 모든 관리자는 동일한 권한을 가지며 관리자 페이지에서 다른 관리자 계정을 추가·수정·삭제·초기화할 수 있다.

이 문서는 관리자 인증과 계정 관리만 다룬다. Firestore 업무 데이터의 MySQL 이전과 Firebase Storage의 `/uploads` 이전은 별도 단계로 진행한다.

## 활성화 선행조건

이 인증 전환은 Firestore 업무 데이터와 관리자 쓰기 API가 MySQL/PHP로 이전된 뒤 마지막 단계에서 활성화한다.

현재 `firestore.rules`는 일반 문서 쓰기, 관리자 활동 로그, 관리자 전용 방문 통계 조회를 `request.auth != null`인 Firebase 로그인 사용자에게만 허용한다. 따라서 Firebase Auth를 먼저 제거하면 공지·갤러리·설정 등 기존 관리자 화면의 Firestore 저장 기능이 모두 실패한다.

- 미디어 저장소를 카페24 `/uploads`로 이전한다.
- Firestore 기반 업무 데이터와 관리자 로그를 MySQL/PHP API로 이전한다.
- 기존 관리자 화면이 PHP API만 사용하도록 전환하고 검증한다.
- 마지막으로 본 문서의 PHP 로그인과 관리자 계정 관리를 활성화한다.

전환이 완료되기 전까지는 기존 Firebase Auth 로그인을 유지한다. 사용되지 않는 PHP 인증 코드를 미리 배포하지 않는다.

## 선택한 방식

카페24 PHP 세션과 MySQL을 사용한다.

- 공유 관리자 계정 하나는 작업자 구분과 비밀번호 인수인계가 어려워 사용하지 않는다.
- 카페24 DB 관리도구에서만 수동 관리하는 방식은 비개발자가 운영하기 어려워 사용하지 않는다.
- 관리자 화면에 `관리자 계정 설정` 메뉴를 추가하여 계정을 직접 관리한다.
- 별도의 역할 구분은 만들지 않는다. 로그인한 모든 관리자는 같은 기능과 권한을 가진다.

## 화면 구성

관리자 메뉴에 `관리자 계정 설정`을 추가하고 `/admin/accounts`에서 다음 기능을 제공한다.

- 관리자 목록 조회
- 로그인 ID, 관리자 이름, 사용 상태, 최근 로그인 일시 표시
- 계정 추가
- 로그인 ID와 관리자 이름 수정
- 계정 삭제
- 임시 비밀번호 설정
- 초기화된 계정의 다음 로그인 시 비밀번호 변경

화면에서 삭제한 계정은 DB에서 즉시 물리 삭제하지 않고 사용 중지 처리한다. 활동 로그와 과거 작업자를 추적하기 위함이다.

## 안전 규칙

- 마지막 활성 관리자 계정은 삭제하거나 사용 중지할 수 없다.
- 현재 로그인한 자기 계정은 계정 관리 화면에서 삭제할 수 없다.
- 모든 관리자는 자기 비밀번호를 변경할 수 있다.
- 다른 관리자의 비밀번호는 조회할 수 없고 임시 비밀번호로 초기화만 할 수 있다.
- 임시 비밀번호로 로그인하면 다른 관리자 기능보다 먼저 새 비밀번호를 설정해야 한다.
- 계정 추가·수정·삭제·비밀번호 초기화는 활동 로그에 작업자와 대상 계정을 기록한다. 비밀번호 값은 기록하지 않는다.

위 제한은 역할 차등이 아니다. 모든 관리자가 동일한 규칙 아래 다른 계정을 관리하며, 전체 관리자 잠김과 실수로 인한 자기 계정 삭제만 방지한다.

## 데이터 구조

### `admin_users`

| 컬럼 | 용도 |
|---|---|
| `id` | 내부 숫자 PK |
| `login_id` | 로그인 ID, UNIQUE |
| `display_name` | 관리자 표시 이름 |
| `password_hash` | PHP `password_hash()` 결과 |
| `active_yn` | 로그인 가능 여부 |
| `must_change_password` | 다음 로그인 시 비밀번호 변경 여부 |
| `failed_login_count` | 연속 로그인 실패 횟수 |
| `locked_until` | 반복 실패에 따른 잠금 종료 일시 |
| `last_login_at` | 최근 정상 로그인 일시 |
| `created_at` | 생성 일시 |
| `updated_at` | 수정 일시 |
| `deleted_at` | 화면에서 삭제한 일시 |

로그인 ID는 수정 가능하다. 다른 데이터와의 관계는 변경 가능한 ID 문자열이 아니라 내부 숫자 PK를 사용한다.

### `admin_sessions`

| 컬럼 | 용도 |
|---|---|
| `session_id_hash` | 세션 식별자의 해시, PK |
| `admin_user_id` | `admin_users.id` FK |
| `created_at` | 로그인 일시 |
| `last_seen_at` | 최근 활동 일시 |
| `expires_at` | 만료 일시 |

한 관리자 계정에는 하나의 활성 세션만 허용하여 현재 Firebase 기반 단일 접속 동작을 유지한다. 다른 기기에서 같은 계정으로 로그인하면 기존 세션을 종료하거나 새 로그인을 거부하는 현재 정책을 그대로 적용한다.

## 서버 구성

PHP는 다음 책임만 가진다.

- DB 연결과 공통 JSON 응답
- 로그인, 로그아웃, 현재 사용자 확인, 비밀번호 변경
- 관리자 계정 목록·추가·수정·삭제·비밀번호 초기화
- 세션 생성·갱신·만료
- 관리자 활동 로그 기록

권장 엔드포인트는 다음과 같다.

- `/api/auth.php`: `login`, `logout`, `me`, `change-password`
- `/api/admin-users.php`: `list`, `create`, `update`, `delete`, `reset-password`

DB 접속정보는 React 환경변수나 Git에 넣지 않고 카페24 서버의 웹 공개 경로 밖 설정 파일에 둔다. 모든 SQL은 PDO prepared statement를 사용한다.

## 인증과 보안

- 비밀번호는 PHP `password_hash()`로 저장하고 `password_verify()`로 확인한다.
- 세션 쿠키는 `HttpOnly`, `Secure`, `SameSite=Lax`를 사용한다.
- 로그인 성공 시 세션 ID를 재발급한다.
- 로그인과 관리자 API는 HTTPS에서만 사용한다.
- 로그인 실패 메시지는 ID 존재 여부를 노출하지 않는 동일한 문구를 사용한다.
- 반복 실패 시 해당 로그인 ID를 일정 시간 잠근다.
- 로그인 이후의 변경 요청은 세션 확인과 CSRF 검증을 모두 통과해야 한다.
- React가 보낸 관리자 ID나 권한 정보를 신뢰하지 않고 PHP 세션의 관리자 정보만 사용한다.
- 비밀번호, 세션 원문, DB 비밀번호는 활동 로그에 남기지 않는다.

## React 변경 범위

- `Login.jsx`: Firebase 로그인 대신 `/api/auth.php` 호출
- `AuthContext.jsx`: `onAuthStateChanged` 대신 `me`, 로그인, 로그아웃 상태 관리
- `adminSession.js`: Firestore 세션 처리 제거 후 PHP 세션 상태 확인으로 교체 또는 삭제
- `AdminLayout.jsx`: PHP 로그아웃과 세션 만료 처리
- `App.jsx`: `/admin/accounts` 라우트 추가
- `menuItems.js`: `관리자 계정 설정` 메뉴 추가
- 신규 `AdminAccountManager.jsx`: 계정 목록과 추가·수정·삭제·초기화 UI

짧은 한국어 UI 문구는 프로젝트 인코딩 규칙에 따라 JS 유니코드 이스케이프 사용을 우선하고, 기존 파일의 인코딩을 보존한다.

## 로그인 흐름

1. 사용자가 로그인 ID와 비밀번호를 입력한다.
2. PHP가 활성 계정과 잠금 상태를 확인한다.
3. `password_verify()` 성공 시 기존 활성 세션 정책을 적용하고 새 세션을 만든다.
4. 임시 비밀번호 계정이면 비밀번호 변경 화면으로 이동한다.
5. 정상 계정이면 관리자 대시보드로 이동한다.
6. React는 새로고침 시 `me` 호출로 로그인 상태를 복원한다.
7. 로그아웃 또는 만료 시 서버 세션을 폐기하고 로그인 화면으로 이동한다.

## 초기 계정 이전

Firebase Auth의 비밀번호를 MySQL로 복사하지 않는다. 기존 관리자별로 임시 비밀번호를 발급하여 `admin_users`에 생성하고 첫 로그인 때 변경하게 한다.

최초 계정은 일회성 서버 스크립트 또는 검증된 SQL/PHP 절차로 생성한다. 비밀번호 해시는 반드시 해당 PHP 환경의 `password_hash()`로 만든다. 평문 비밀번호를 SQL 파일이나 문서에 저장하지 않는다.

모든 관리자가 로그인할 수 없을 때는 카페24 DB에서 임시 비밀번호 해시와 활성 상태를 복구하는 운영 절차를 별도 문서로 남긴다.

## 전환 순서와 롤백

1. 미디어와 Firestore 업무 데이터가 카페24 저장소·MySQL/PHP API로 이전됐는지 확인한다.
2. MySQL 관리자 테이블과 PHP 인증 API를 별도 경로에 배포한다.
3. 테스트 관리자 계정으로 로그인·계정 관리·세션 만료를 검증한다.
4. 기존 관리자를 임시 비밀번호 계정으로 등록한다.
5. React 관리자 로그인을 PHP 방식으로 전환한다.
6. 모든 관리자 기능을 검증한 뒤 Firebase Auth와 관리자 세션 Firestore 사용 코드를 제거한다.
7. 안정화 전에는 기존 배포본과 DB 백업을 보존한다.

문제가 생기면 이전 `dist`를 다시 배포하여 Firebase 로그인 방식으로 되돌리고, 신규 MySQL 관리자 테이블은 보존한 채 원인을 수정한다.

## 검증 항목

- 정상·오류 비밀번호 로그인
- 존재하지 않는 ID 로그인
- 반복 실패 잠금과 잠금 해제
- 새로고침 후 세션 유지
- 로그아웃과 세션 만료
- 동일 계정 중복 로그인 제한
- 관리자 추가·수정·삭제·초기화
- 마지막 활성 관리자 삭제 차단
- 자기 계정 삭제 차단
- 임시 비밀번호 최초 로그인 시 변경 강제
- 비활성·삭제 계정 로그인 차단
- SQL 삽입 문자열과 CSRF 요청 차단
- 활동 로그에 작업자와 대상 계정 기록
- 카페24 HTTPS 운영 환경에서 쿠키 동작
- production build와 기존 관리자 화면 회귀 테스트

## 제외 범위

- 관리자별 역할과 세부 메뉴 권한
- 이메일 인증과 이메일 비밀번호 찾기
- 소셜 로그인
- 2단계 인증
- 교인 일반회원 계정
- Firestore 업무 데이터의 MySQL 이전
- Firebase Storage 파일의 카페24 이전

향후 실제 필요가 확인되기 전에는 위 기능을 추가하지 않는다.
