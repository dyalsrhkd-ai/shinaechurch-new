# 홈페이지 관리자 「신애교회 앱관리」 메뉴 — 설계

작성 2026-10-08 · 요청 요셉님 · 확정 시안 `.superpowers/brainstorm/138152-1791443627/content/app-admin-v4.html`

## 목적

홈페이지 관리자 화면에서도 교인앱(공지·회원 승인·투표·일정·신애톡 등 **앱 관리 전체**)을 할 수 있게 한다.
앱과 웹이 **완전히 같아야** 한다 — 따로 그린 비슷한 화면이 아니라 **앱 화면 그 자체**를 관리자 화면 안에 띄운다.

## 화면 (시안 4 그대로)

- 관리자 사이드바 맨 아래에 묶음 「교인 소통 앱」 › **「📱 신애교회 앱관리」**.
- 위 줄: 위치 표시 · **모양 단추 3개** · **폭 칸(px)** · 「새 창으로 열기 ↗」.
  - 작은 폰 344(폴드 접음) / 보통 폰 412(갤럭시·아이폰, 기본) / 넓은 화면 860(폴드 펼침·태블릿).
  - 기기 목록은 두지 않는다 — 앱 모양은 폭 기준점(360·420·700px, `shinae-community/src/styles.css` 의 `@media`)에서만 바뀌므로 세 모양이면 모든 기기를 덮는다.
- 본문: 검은 휴대폰 틀 안에 앱. 틀 오른쪽 **손잡이를 끌면** 폭이 바뀌고(**320~1100**), 오른쪽 아래에 「폭 ○px → 앱은 ○○ 모양」.
- **기준은 폰·폴드에서 쓰는 앱이다(요셉님 10/8).** 앱에서 안 보이는 것은 웹에서도 안 보여야 한다. 앱은 폭 1150px 를 넘으면 「함께 묵상해요」(`right-column`) 같은 넓은 PC 전용 칸을 띄우는데(`styles.css` `@media(max-width:1150px)` 에서만 숨김), 폰·폴드는 그 폭까지 가지 않는다 → **폭 상한 1100px** 로 묶어 그런 칸이 절대 나오지 않게 한다. 앱 CSS 기준점이 바뀌면 이 상한도 같이 고친다(시험이 잡게).
- 고른 폭은 이 브라우저에 기억한다(localStorage, 못 써도 기본 412 로 동작).
- **흐림 금지**: 틀 높이는 화면 높이에 맞춰 늘리고 기본은 100% 로 그린다. 폭이 본문보다 넓을 때만 줄이며, 그때도 `transform: scale` 이 아니라 CSS `zoom` 으로 다시 그려 글씨·선이 선명해야 한다(시안은 scale 이라 교회일정이 흐렸다).
- 태블릿(관리자 폭 768~1024): 보통 폰·작은 폰은 100%, 넓은 화면은 zoom 으로 맞춤. 홈페이지 사이드바 자체는 이번에 바꾸지 않는다(관리자 전체에 영향).

## 구조

### 1) 앱(shinae-community) — 「관리 모드」 `?embed=admin`

주소에 `embed=admin` 이 있으면:
- 첫 화면 표어 애니메이션(`Intro`)·첫 사용 안내(`FirstRunGuide`)·업데이트 안내(`UpdateBanner`)·알림 권한 묻기를 띄우지 않는다.
- 로그인 화면에서 가입 신청으로 가는 길을 숨긴다(첫 실행이면 가입부터 여는 규칙도 끈다).
- 승인된 관리자가 아니면 「신애교회 앱관리는 앱 관리자 계정만 쓸 수 있습니다」 안내 + 로그아웃 단추만.
- 그 밖의 화면·동작은 앱과 한 글자도 다르지 않다(같은 코드).

보안 — `public/_headers` 에 `Content-Security-Policy: frame-ancestors 'self' http://www.shinaechurch.co.kr https://www.shinaechurch.co.kr http://shinaechurch.co.kr https://shinaechurch.co.kr http://localhost:*` (다른 사이트가 앱을 몰래 띄우지 못하게). Worker CORS 는 앱 주소 그대로라 바꿀 것 없음.

배포: Pages 만. **APK 새 버전 필요 없음**(폰 앱은 `embed` 없이 열려 바뀌는 것 없음).

### 2) 홈페이지(shinaechurch-new) — 운영 반영은 「다리 스크립트」

운영 홈페이지 관리자는 지금 소스로 다시 빌드한 것이 아니다(Cafe24 전환 전). 그래서 지금까지처럼
**운영 `index.html` 에 붙은 다리 스크립트**(`public/app-install-links.js` → FTP `app-install-links-20261002.js`)를 늘려 반영한다.

- 사이드바에 「교인 소통 앱」 묶음과 메뉴 한 줄을 끼워 넣는다(기존 메뉴 모양을 그대로 복제해 쓴다).
- 메뉴 주소는 운영 라우터가 아는 **`#/admin/dashboard?view=app`**(모르는 경로로 가면 라우터가 튕길 수 있음). 이 주소일 때 다리 스크립트가 본문을 앱관리 화면으로 바꿔 그리고, 다른 주소로 가면 원래 본문을 되돌린다. 메뉴 선택 표시도 맞춘다.
- 대시보드의 「교인앱 관리 열기」 링크는 이 메뉴로 보낸다(새 창 링크는 화면 안 「새 창으로 열기」로).
- 배포: `scripts/footer-deploy.mjs` 에 새 단계(`app-admin`) — 운영 파일 백업 → 업로드 → 내려받아 같은지 대조 → `index.html` 의 캐시 꼬리표 올림. **FTP 비밀번호는 요셉님이 직접 입력**(표준입력, 파일·대화에 남기지 않음).

소스도 같이 맞춘다(나중에 전체 빌드할 때 그대로 쓰이게): `src/pages/admin/menuItems.js` 에 메뉴, `src/pages/admin/app/AppAdmin.jsx` 새 화면, `App.jsx` 라우트 `/admin/app`, 대시보드 링크. 이 저장소에는 다른 작업(Cafe24 전환)의 미커밋 변경이 많으므로 **내가 바꾼 파일만** 커밋한다.

## 오류·예외

- 앱이 안 뜨면(네트워크·차단) 틀 안에 「앱을 불러오지 못했습니다 — 새 창으로 열기」.
- 홈페이지 주소가 http 라 iframe 안 앱의 로그인 정보는 그 화면 전용으로 따로 저장된다 → 처음 한 번 앱 관리자 로그인. 아이폰 사파리는 오래 안 쓰면 다시 로그인.
- 다리 스크립트가 사이드바·본문을 못 찾으면(운영 화면이 바뀐 경우) 아무것도 바꾸지 않고 대시보드 링크만 남긴다.

## 시험

- 앱: 관리 모드 단위 시험(인트로·가입·업데이트 안내 숨김, 관리자 아닌 계정 차단), 기존 단위·`screen-fit` 화면 시험 통과.
- 홈페이지: 다리 스크립트 브라우저 시험 — 메뉴 끼움, `?view=app` 본문 전환·복귀, 모양 단추·폭 칸·손잡이, 3모양 × 탭 5개(나눔·교회일정·신애톡·교회소식·교인 관리) **흐림·넘침 없음**, 폭 최대(1100)에서도 「함께 묵상해요」가 안 보임, 태블릿 폭(768·1024).
- 운영 반영 후: 운영 관리자에서 같은 확인(공지는 쓰기 화면까지만, 실제로 올리지 않음). `footer-browser.mjs` 점검 통과.

## 하지 않는 것

- 홈페이지 공지 ↔ 앱 공지 자동 연동(별개 기능).
- 홈페이지 관리자 계정으로 앱 자동 로그인(계정 체계가 달라 이번엔 따로 로그인).
- 홈페이지 사이드바 반응형 개편.
